# User Guide Quick Reference

1. Segment at headings, then classify each unit with the action/cognition and acquisition/application compass.
2. Keep Markdown structure scannable: one H1 and a consistent H2/H3 hierarchy.
3. For tasks, state the goal, prerequisites, ordered steps, and expected result.
4. Use direct active language, consistent terminology, descriptive links, and distinct code/UI formatting.
5. Emit classification confidence; low-confidence units are not topic-completeness scored.
6. Audit first; apply only deterministic safe fixes unless product owners approve semantic changes.
6. Never invent facts, product behavior, metrics, or missing procedures.
